## 拿到数据之后看三件事

**延迟和丢包。** ping 一百次看平均值和丢包率，别只看最低值。`ping.pe` 这类多节点平台能一次看到全国三网的表现，重点看晚八点到十一点这个时段，白天的数字好看不代表晚高峰好看。AkkoCloud 伦敦的第三方实测里，有人本地 ping 到 173ms、三网平均 167ms，也有人测出 200ms 上下，差异来自你所在的城市和运营商。

**ASN 归属。** 用 ipinfo.io 一类工具查这个 IP 的 ASN 和 company type。有测评给出的判断口径是 ASN 与 Company 的 type 都是 isp，才算双 ISP 住宅 IP。AkkoCloud 伦敦是机房 IP，这一项查出来不会是 isp，后面单说这意味着什么。

**路由走向。** 电信看是否走 59.43 段的 CN2 GIA 或 AS9929，联通看 AS9929 或 AS10099，移动看 CMIN2（AS58807）。有第三方对 AkkoCloud 伦敦做过跟踪，电信去程走 CN2 到法兰克福再转伦敦，联通走 AS10099 经法兰克福落地，移动走 CMIN2，三条线最终都从德国进英国。这个走向解释了为什么它的延迟比普通英国机房稳定，也解释了为什么它比圣何塞慢 50ms 左右。

## 200ms 是物理距离，不是线路差

伦敦到国内直线距离八千公里往上，光在光纤里跑一个来回就要 80ms 起步，加上中间路由绕行和跨境互联的排队，200ms 属于这条线路的正常水位。任何英国机房都绕不开这个数，换哪家都一样。有测评把这句话写得很直白：英国机房到大陆延迟 200ms+ 是物理距离决定的。

所以拿 200ms 去判断“这家线路好不好”是错的方向。同样 200ms，该看的是丢包率高不高、晚高峰会不会掉到 300ms 以上、回程是不是稳定走 CN2 GIA 不绕美国。这三项才是商家能控制的部分，AkkoCloud 在回程上做的是强制三网 GIA，属于它的卖点。

对延迟敏感的业务，比如实时交互或者 SSH 敲命令要跟手，英国节点本身就不是好选择。标准做法是在香港或日本加一台中转，英国这台只负责出口 IP，500Mbps 端口跑中转是够用的。
